## 2. Reuse and new code per novelty part

Common facts: frozen DenseNet-121 average-pool features (1024-d) are cheap to extract once. `lungai/evaluation/source_probe.py` already has `_sample`, `_features` (compiled graph, padded batch), `probe` (StandardScaler + multinomial logistic regression, balanced accuracy, within-class). `lungai/training/train_v6.py` has `load_split`, `cached_batch`, `predict_cached`. `lungai/evaluation/metrics.py` has `bootstrap_ci`, `wilson_ci`, `metrics_from_confusion`. Model loading: `lungai.models.densenet.load_checkpoint`; the penultimate layer is the named Dense features layer built in `lungai/models/densenet.py`.

### C1 Spectral source-disease map (no training)
- Reuse: `source_probe._sample/_features/probe`, `train_v6.load_split`, `metrics.bootstrap_ci`.
- New: `lungai/novelty/spectral.py` (radial FFT band masks on the 224x224 image; octave edges fixed in the protocol; `band_filter(img_uint8, lo, hi)`); `lungai/novelty/spectral_map.py` (CLI: per band, extract features with the ImageNet and served-model extractors, fit source probe and disease probe on train, score on test, within-source disease macro-F1, bootstrap CIs; writes `artifacts/novelty/c1_spectral_map.json`; also emits validation-split scores for C2 band selection); `lungai/novelty/render_c1.py` (figure and macros).
- Outputs: table band x {source balanced accuracy, disease macro-F1, within-class source accuracy, SDS index}; figure `docs/figures/fig_spectral_map.*`; macros `\RSpec...`.
- Caveat to state: the cache is already low-passed at native resolution (sigma 1.0), so the top band is attenuated. Robustness check: repeat on the `v6_build_002_no_filters` cache.
- CPU time: ~1,500 train + 1,000 test images x 8 bands x 1-2 extractors = 20-40k forward passes. About 1-2 h alone; 3-5 h while training runs. Start with the ImageNet extractor only.
- Depends on: nothing.

### C2 Band-stop suppression plus retraining
- Reuse: `scripts/data/make_ablation_build.py` pattern (new build directory, same manifest and split fingerprint); `lungai/training/train_v6.py`; `scripts/pipeline/run_followups.py` (add job tag, e.g. `_r6bs`); `lungai/evaluation/aggregate_seeds.py` (ablation list); `render_docs.py`.
- New: `lungai/novelty/select_bands.py` (validation-only rule fixed in advance, reads C1 validation scores); `scripts/data/make_bandstop_build.py` (applies `band_filter` to the existing cache .npy files, ~15.7k files, minutes, no re-decoding); after training, re-run `source_probe --build ... --checkpoint ...` on the new model.
- Outputs: reports `artifacts/evaluation_reports/v6_r6bs_*`; comparison with runs 2-5; post-suppression source probe; macros `\RBs...`.
- CPU time: one run ~6-8 h plus evaluation ~30 min; two more seeds for a journal claim (two further nights). Cannot start until run 5 finishes (one heavy job at a time).
- Depends on: C1 (band choice) and run 5 finished.

### C3 INLP source removal in feature space
- Reuse: `source_probe._features/probe`, `load_checkpoint`, `predict_cached`; `aggregate_seeds` reporting style.
- New: `lungai/novelty/inlp.py` (iterative nullspace projection with a linear source classifier; iteration count and tolerance fixed in the protocol; projection matrix saved); `lungai/novelty/features.py` (extract and cache penultimate/pooled features for train/val/test/Montgomery to `artifacts/novelty/features_*.npy`, shared with C4); `lungai/novelty/inlp_eval.py` (project, retrain linear disease head on train, report source-probe accuracy and disease macro-F1/AUC per iteration; Montgomery once).
- Outputs: curve source accuracy vs disease F1 per iteration (`fig_inlp.*`), table, macros `\RInlp...`.
- CPU time: feature extraction for ~15.7k images ~1-2 h alone (shared with C4); INLP itself minutes.
- Depends on: shared feature cache only.

### C4 Leave-one-source-out matrix
- Reuse: feature cache from C3, `metrics.py`, sklearn heads as in `probe`.
- New: `lungai/novelty/loso.py` (for each held-out source with at least two classes, train a linear head on the other sources, test on the held-out source; repeat on raw, INLP-projected (C3) and band-stop (C2) features); outputs `artifacts/novelty/c4_loso.json`, `fig_loso_matrix.*`, macros `\RLoso...`.
- Caveat: classes tied to one source (Effusion, Nodule/Mass all NIH; Pneumonia mostly Kermany) cannot be tested on hold-out; report classes present in the held-out source plus a binary abnormal-vs-normal view. Hyper-parameters on validation only; test split once for the final table; Montgomery once.
- CPU time: minutes once features exist.
- Depends on: C3 feature cache; C2/C3 variants optional.

### Dependency summary
The feature cache (C3/C4) and C1 are independent and can run first. C2 needs C1 and a free CPU after run 5. C4 variants reuse C3 projections and, if available, C2 features.

## 4. Risks and integrity requirements

- Fix and record in the repository before results: band edges, SDS definition, probe regularisation and sampling counts, INLP iterations, band-selection rule, LOSO inclusion rule, success and failure criteria. Say "fixed in advance and recorded in the repository", never "pre-registered".
- Selection and tuning on validation only; test split and Montgomery evaluated once per final configuration, with the order logged in the protocol. Montgomery was already seen for runs 1-3; state this.
- All numbers via generated macros (extend `render_docs.py` or a renderer it calls); never hand-typed. Shortcut evidence stays "indirect / consistent with": the probe shows information is available, not that it is used.
- Leakage statements carry the patient-identity caveat (4,130 TBX11K and COVID-19 Radiography rows grouped per image).
- Scientific risks: the cache is already low-passed and CLAHE-processed, so spectra are not those of raw images; source and class are confounded, so a disease probe can itself use source cues (report within-source disease scores); band-stop may lower internal accuracy without helping external; INLP may collapse disease accuracy (a finding, not a failure); single seed for C2; Montgomery is small (138) and binary.
- Operational risks: 8 GB RAM and one heavy job at a time; Windows heredoc backslash and BOM quirks (use the Edit tool or Python with `chr(92)` for LaTeX); no pytest or npm while training.
- Novelty is claimed only after the extended literature search; no state-of-the-art or clinical claims.
