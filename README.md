## 📌 Project Overview

**LungAI** is an end-to-end Deep Learning and Full-Stack clinical decision-support ecosystem for robust, automated multi-class thoracic disease classification from chest radiographs (X-rays).

- **Core Objective**: Provide an auditable, automated decision-support pipeline for clinical triage across time-sensitive thoracic diseases with visual interpretability and domain generalization safeguards.
- **Central Research Question**:  
  > *"Can a multi-source six-class chest X-ray classifier learn disease-relevant representations that generalize across independent acquisition sources, and can a domain-generalization strategy improve cross-source performance compared with a standard DenseNet-121 baseline?"*
- **Input**: Planar chest radiographs (`JPEG`, `PNG`, `BMP`, `TIFF`, `WebP`, $\le$ 10 MB).
- **Two-Stage Input Gate**: Intercepts non-radiographic uploads, corrupt files, and axial CT scans before neural inference, returning structured `HTTP 422 Unprocessable Entity`. Stage 2 uses a trained classifier ($\tau = 0.83$) when `models/cxr_gate_model.keras` is present; that file is not in this repository, and without it a much weaker symmetry/contrast heuristic is used (`/api/v1/health` reports which).
- **Production Architecture**: **Model D** — DenseNet-121 with Contrast-Limited Adaptive Histogram Equalization (CLAHE) and Spatial Gaussian Low-Pass Preprocessing ($\sigma = 1.0$) to suppress high-frequency scanner noise shortcuts.
- **Output**: 6-class softmax scores (not calibrated probabilities), an inconclusive state when the top score is below `CONFIDENCE_FLOOR` (default 0.5), urgency labels (`Emergency`, `Urgent`, `Routine`, `Review`), Grad-CAM overlay, and stored records including all six scores and the checkpoint SHA-256.

## 🛡️ Two-Stage Defense-in-Depth CXR Validation Gate

Standard deep learning classifiers suffer from **silent failure**—confidently predicting thoracic diseases on non-medical photos, lateral views, or axial CT scans. LungAI implements a two-stage pre-inference validation gate in [`backend/ml/cxr_gate.py`](backend/ml/cxr_gate.py):

```mermaid
flowchart TD
    Upload[Incoming Image Upload] --> Stage1{Stage 1: Biophysical Heuristics}
    Stage1 -->|High Color Saturation / Non-Greyscale| Reject1[HTTP 422 Rejection]
    Stage1 -->|Dynamic Range < 60%| Reject1
    Stage1 -->|Aspect Ratio Out-of-Bounds| Reject1
    
    Stage1 -->|Passes Biophysical Bounds| Stage2{Stage 2: Deep Anatomical Gate}
    Stage2 -->|P CXR < tau = 0.83| Reject2[HTTP 422: Not a Planar CXR]
    
    Stage2 -->|P CXR >= 0.83| Validated[Validated Planar CXR]
    Validated --> Preprocessing[Model D Preprocessing & Inference]
    
    Reject1 --> Halt[Halt: No Inference & No DB Persistence]
    Reject2 --> Halt
```

### Verification & Calibration Facts ($\tau = 0.83$)
- **Functional Validation Cohort ($N = 125$)**: 48 genuine planar CXRs and 77 non-CXR images (axial CT slices, natural animals/landscapes, non-radiographic clinical photos).
- **Measured Performance at $\tau = 0.83$**: **100.0% Sensitivity** (48/48 CXRs passed), **100.0% Specificity** (77/77 non-CXRs rejected), **ROC-AUC = 1.0000**.
- **The "Cat Defect" Discovery**: At threshold $\tau = 0.70$, a high-contrast domestic cat photograph was misclassified as "Normal" (whiskers mimicked vascular markings). Increasing the production threshold to $\tau = 0.83$ permanently resolved this defect (cat scored 0.7410 and was rejected).
- **Structured HTTP 422 Response**: Rejections return clear diagnostic error messages without invoking neural feature extractors or persisting empty patient records.
- *Methodological Limitation*: Threshold $\tau = 0.83$ was selected on this evaluation cohort; values reflect functional verification estimates rather than unbiased external generalization.
- *Reproducibility note*: the trained gate model and its evaluation images are not included in this repository, so the figures above cannot be reproduced from it. The heuristic fallback used without the model accepts simple symmetric shapes (for example a grey circle on a black background) as chest X-rays.

### Patient-Level Partitioning & Forensic Safeguards
- **Patient-Level Splitting (with a known leak)**: Splitting was performed by the manifest's `patient_id` (10,270 distinct IDs):
  - **Training Split (70.14%)**: 7,398 images / 7,189 patient IDs
  - **Validation Split (14.97%)**: 1,579 images / 1,540 patient IDs
  - **Internal Test Split (14.89%)**: **1,570 images / 1,541 patient IDs**
- **Known Leakage**: for the `Existing_*` (Kermany, COVID-19 Radiography DB, Shenzhen) and TBX11K sources, the manifest assigns one synthetic patient ID per image, so 8,478 of the IDs do not identify real patients. The Kermany filenames still encode the patient (`person###`, `IM-####`): **154 of the 1,570 test images (9.8%) belong to patients who also have images in the training split** (110/210 Existing_Pneumonia, 44/180 Existing_Normal test images). Patient identity for the renamed COVID-19 and Shenzhen files cannot be recovered. Internal test metrics below are therefore optimistically biased.
- **Label Proxy**: TBX11K `sick_but_no_tb` (abnormal, not TB, cause unspecified) is mapped to Pneumonia and makes up 1,395 of the 2,805 Pneumonia labels.
- **Acquisition-Site Confounding**: Quantified via Cramér's V statistic: **$V = 0.7654$**, confirming heavy source-disease correlation and underscoring the critical necessity of domain generalization.
- **Cross-Modality Decontamination**: Programmatic radial gradient profiling identified and purged 287 contaminated axial CT slices from legacy public collections.

### Key Findings and Caveats:
1. **Model D scored highest on the internal test split** (+6.75 accuracy points over ERM). Each paradigm was trained once (seed 42, 4 epochs), and the comparison is made on the test split itself, so the size of the difference is not established.

## ⚠️ External Generalization Audit: Montgomery County Cohort

Model D was evaluated zero-shot on the quarantined **Montgomery County Chest X-ray Dataset** ($N = 138$ scans: 58 confirmed Tuberculosis cases, 80 Normal subjects):

| Metric / Dimension | Reported Result | Diagnostic Significance |
| :--- | :---: | :--- |
| **Binary Abnormal Sensitivity** | **100.0%** (58 / 58) | Every TB case was assigned some non-Normal class, but so was every normal scan (see specificity), so this does not indicate screening ability. |
| **Tuberculosis Specific Recall** | **0.0%** (0 / 58) | Severe diagnostic collapse; misclassified as Nodule/Mass. |
| **Normal Specificity** | **0.0%** (0 / 80) | Normal scans misclassified as abnormal (predominantly Nodule/Mass). |
| **Predominant Predicted Class** | **Nodule / Mass** (98.6%) | Extreme prediction bias triggered by scanner sensor shift. |

> **Forensic Root Cause**: The Montgomery scans were digitized from analog film at high optical resolution ($4020 \times 4892$), whereas training sources used direct digital radiography (DR/CR). The sharp film grain noise and optical scan borders yielded approximately 4&times; higher Laplacian edge variance (1,580 vs 373 on digital CXRs), which was misinterpreted by convolutional filters as parenchymal nodular boundaries. This demonstrates that internal validation accuracy alone cannot guarantee cross-sensor generalization.

## 📥 Model Distribution & Checkpoints

The Model D checkpoint (`densenet121_frequency_v5.h5`) is **not** in this repository (`*.h5` is gitignored) and there is no GitHub release yet, so `download_model.py` currently gets HTTP 404. Copy the checkpoint into `models/` (or point `MODELS_DIR` at its folder) before starting the backend.

Without a checkpoint the backend still starts, but `/api/v1/health` reports `"status": "degraded"` with the reason, and `POST /api/v1/predict` returns **HTTP 503**. It never returns placeholder predictions. When a checkpoint is loaded, its SHA-256 is reported by `/health` and stored with every prediction.

To verify or download model checkpoints (set `LUNGAI_MODEL_URL` to override the source):
```bash
python backend/ml/download_model.py
```

## ⚡ Quickstart Guide

### Prerequisites
- **Python**: `3.10` to `3.12`
- **Node.js**: `18.x` or `20.x`

### 1. Clone & Environment Setup
```bash
git clone https://github.com/KSathwik/Lung_Disease_Detector.git
cd Lung_Disease_Detector

python -m venv .venv
# Windows PowerShell:
.\.venv\Scripts\Activate.ps1
# Linux / macOS:
source .venv/bin/activate

pip install -r backend/requirements.txt
```

### 2. Place the Model Checkpoint
Copy `densenet121_frequency_v5.h5` into `models/` (see [Model Distribution](#-model-distribution--checkpoints)).

### 3. Run Backend API Server
```bash
python backend/main.py
```
- **API Base URL**: `http://localhost:8000` (binds to `127.0.0.1` by default; set `API_HOST` to change it)
- **Interactive OpenAPI / Swagger Documentation**: `http://localhost:8000/docs`
- **Access control**: without `LUNGAI_API_KEY`, `/api/*` only answers clients on this machine. To allow other machines, set `LUNGAI_API_KEY` and send it as the `X-API-Key` header (build the frontend with `REACT_APP_API_KEY` set to the same value).

### 4. Run Frontend React Client
```bash
cd frontend
npm ci
npm start
```
- **Clinical Web Application**: `http://localhost:3000` (API calls go to `/api/v1`, which the dev server proxies to port 8000)

## 📌 Limitations & Responsible AI Guidelines

1. **Sensor Domain Discrepancies**: While Model D achieves 82.93% accuracy on the internal test split, every Montgomery image (including all 80 normals) was classified as abnormal, mostly Nodule/Mass. Predictions on images from new hospitals or scanners are not reliable.
2. **Internal Test Leakage and Source Confounding**: 9.8% of internal test images share a patient with the training split, and several classes come almost entirely from one source dataset (all COVID-19 from one database). Internal metrics are optimistic.
3. **Class Imbalance & Pathological Coverage**: Acute conditions (COVID-19 F1: 97.01%, Normal F1: 89.58%) achieved superior discrimination compared to morphological nodular lesions (53.03%) and effusions (55.32%).
4. **Validation Gate Calibration Scope**: The production threshold $\tau = 0.83$ was selected on the 125-image evaluation cohort; performance represents a functional verification estimate. Without the trained gate model (not in this repository) a weak heuristic is used.
5. **Clinical Scope**: LungAI is a research prototype, not a medical device. Final diagnosis and therapeutic interventions must always be rendered by licensed medical professionals.
